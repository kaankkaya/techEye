System Architecture

📷

Camera Module (React Native Camera)

Input: Real-time video stream from device camera at target ~1 fps.

Output: Raw frame buffer (RGB, 640×480 or device-native resolution).

Permissions are requested at app launch. Camera preview is rendered to the screen with an overlay HUD for controls.

🧠

YOLO11n Inference (ONNX Runtime)

Input: 640×480 RGB frame, preprocessed and normalized.

Processing: Forward pass through the YOLO11n model to generate bounding boxes, class predictions, and confidence scores.

Output: Detections object: {class, bbox: [x, y, w, h], confidence}.

Latency: ~80–120ms per frame on modern mobile hardware (A14+, Snapdragon 8xx series).

📏

Distance Estimation (Pinhole Camera Model)

Input: Bounding box height (pixels) and known object reference height (e.g., 170 cm for adult human).

Math: distance = (focal_length × object_height) / bbox_height_pixels

Focal Length: Calibrated per device; stored as a constant derived from camera intrinsics.

Output: Estimated distance in metres, rounded to 1 decimal place.

Accuracy: ±15–20% depending on object orientation and camera angle.

🔊

Filtering, Prioritization & Speech

Filtering: Only detections within a proximity threshold (default: 5 metres) are retained. Confidence threshold: >0.5.

Prioritization: person > vehicle (car, bus, truck, bicycle) > animal (dog, cat). Top detection per frame is selected.

Speech: Turkish sentence is generated and played via system TTS. Example: "2.3 metre uzağınızda bir kişi var."

Haptics: If distance < 1.5 metres, a haptic pulse is triggered (intensity proportional to proximity).

Machine Learning Model Details

Deep dive into the YOLO11n model, its quantization, and how distance estimation works at the computational level.

YOLO11n — Architecture & Training

Base Model: Ultralytics YOLOv11 Nano, a lightweight convolutional neural network optimized for real-time object detection on edge devices.

Key Specifications:

  • Parameters: ~2.6M trainable parameters (vs. YOLOv5n's 1.9M and YOLOv8n's 3.2M — a balanced middle ground).
  • Input Resolution: 640×640 or adaptive (down-scales to 480 or 640 depending on device and performance budget).
  • Backbone: Compact convolutional stack with depth-wise separable convolutions for efficiency.
  • Neck: PAFPN (Path Aggregation Feature Pyramid Network) for multi-scale feature fusion.
  • Head: 3-output decoupled detection head (bbox regression, class prediction, objectness).
  • Training Dataset: COCO 2017 + custom fine-tuning on vision-assistance scenarios (Turkish urban environments).

Why YOLO11n?

  • Small model footprint (~10 MB ONNX) fits in memory on budget Android/iOS devices.
  • Inference latency (80–120 ms) is real-time friendly for a ~1 fps pipeline without dropping frames.
  • Excellent accuracy on person/vehicle/animal classes — the critical categories for navigation safety.
  • ONNX export is mature and well-supported by mobile runtimes.

Model Quantization & Export

Quantization Strategy: The YOLO11n model is exported to ONNX format with optional INT8 quantization for further memory and latency reduction.

yolo export model=yolov11n.pt format=onnx half=False dynamic=False
  • Float32 Model: ~10 MB, used in production for maximum accuracy.
  • INT8 Quantized (optional): ~2.5–3 MB, can reduce latency by 10–20% but may lose 1–2% accuracy.
  • Runtime: ONNX Runtime (ort-mobile for iOS, ort-android for Android) handles inference.
  • Input Preprocessing: Frames are resized, normalized to [0, 1] range, and converted to planar RGB (RRRGGGBBB).
  • Output Postprocessing: Raw predictions are decoded; NMS (Non-Maximum Suppression) filters overlapping boxes. Threshold: 0.5 IoU, 0.4 confidence.

Distance Estimation Algorithm

Method: Pinhole Camera Model — a classical computer vision approach for monocular depth estimation.

Formula

distance (m) = (focal_length_px × object_height_m) / bbox_height_px

Example Calibration

focal_length_px = 800 (device-specific, derived from camera intrinsics)
object_height_m = 1.70 (average adult human)
bbox_height_px = 120 (detected bounding box height)
→ distance = (800 × 1.70) / 120 ≈ 11.3 metres
  • Reference Heights: person: 1.70 m, car: 1.50 m, bicycle: 1.80 m, dog: 0.50 m.
  • Focal Length Calibration: Performed during device setup via a known reference object (e.g., a card at a fixed distance).
  • Accuracy Limits: ±15–20% error due to perspective distortion, tilted camera angles, and occlusion.
  • Fallback Behavior: If distance is uncertain (low confidence detection or extreme angle), directional prefixes are used instead: "Önünüzde bir kişi var" ("There is a person ahead").

Detection Filtering & Prioritization Logic

Per-Frame Pipeline:

1️⃣

Confidence Thresholding

Discard detections with confidence < 0.5. This filters out weak predictions and reduces false positives.

2️⃣

Proximity Filtering

Only retain detections within the proximity threshold (default: 5 metres). Beyond this range, objects are not relevant for immediate navigation.

3️⃣

Class Prioritization

Sort remaining detections by class priority: person (1) > vehicle (2) > animal (3). Within a class, closest object wins.

4️⃣

Speech & Haptic Output

Announce the top detection. If distance < 1.5 metres, trigger a haptic pulse with intensity proportional to proximity. Repeat detection only if the object class or distance changes significantly (> 0.5 m delta).

Accessibility & Design Philosophy

EyeTech is built from the ground up for blind and low-vision users. Every design decision prioritizes clarity, usability, and dignity.

Core Principles

Audio-First Interface

The app speaks what it sees. Every interaction is spoken aloud in clear, calm Turkish. Users do not need to look at a screen — the app adapts to their needs, not the other way around.

Offline & Private

All processing happens on the device. No data leaves the phone. Users retain complete privacy and control, with no dependency on cloud services or network connectivity.

Haptic Feedback

Close objects trigger haptic warnings (vibration), reinforcing audio cues. Haptics are subtle and informative — never jarring or overwhelming.

Oversized Touch Targets

All buttons and interactive elements are at least 64×64 dp — well above the minimum 44 dp. This ensures users can tap accurately without seeing the screen.

One Action Per Screen

Complexity is reduced to essentials. Each screen has a single primary task: scan, select voice, adjust settings. No nested menus or hidden options.

High Contrast & Large Type

Text is oversized (18 sp minimum) on near-black backgrounds with warm orange accents. For partially sighted users, the visual design is as accessible as the audio one.

Accessibility Features

  • VoiceOver / TalkBack Support: Native screen reader integration on iOS and Android. Every UI element has descriptive labels and hints.
  • Reduced Motion: Respects system Reduce Motion setting. Animations are skipped; content remains visible immediately.
  • Dark Mode Native: The UI is built on a dark palette — no light mode option. This reduces eye strain for all users and aligns with accessibility best practices.
  • High Contrast Text: White text on near-black (#0F0A08) achieves WCAG AAA contrast ratio (>7:1). Secondary text at 60% opacity maintains legibility.
  • Turkish Language Support: Full localization in Turkish, with culturally appropriate speech patterns (formal "siz" form).
  • Accessibility Labels & Hints: Every button carries a descriptive label (what it is) and a hint (what it does). Example: label: "Tara", hint: "Kamera ile nesne algılamayı başlatır" ("Starts detecting objects with the camera").
  • No Decorative Graphics: The app has no unnecessary icons or imagery — only functional UI. The brand is expressed through typography and the orange accent, not visual noise.

Design System (UI & Interaction)

Color & Contrast

Background: #0F0A08 (warm near-black). Accent: #F97316 (safety orange). Text: #FFFFFF (pure white) with 60% opacity for secondary. Contrast Ratio: 7:1+ (WCAG AAA).

Typography

Font: Inter (400 regular, 700 bold). Sizes: 18–28 sp minimum. Line Height: 1.5–1.6 for readability. Letter Spacing: Increased on all-caps labels (0.8px).

Spacing & Padding

Scale: 4/8px base (gaps of 8, 12, 16, 24, 32 dp). Screen Padding: 24–32 dp on all edges. Card Margins: Generous whitespace between interactive elements.

Button & Touch States

Size: 160×64 dp minimum. Feedback: Haptic pulse (medium) + touch opacity dimming (visual feedback for sighted users). States: Idle (solid color), pressed (darker shade), disabled (lower opacity).
